   **Ordered Diagnostic Checklist (Cheapest-First)**
   1. **Confirm OOM vs. Other Kill Causes** (Free)
      - Check `dmesg | grep -i oom` or `journalctl --since "3am"` for `OOMKILL`
      - Rule out `SIGKILL` from scheduler, `SIGTERM` from timeout, or `Segmentation fault`
   2. **Check for Duplicate/Overlapping Executions** (Free)
      - 3am batch jobs often run multiple times due to cron misconfig, queue backlog, or failed retries
      - Check scheduler logs (cron, Airflow, Celery, systemd timers) for concurrent runs
   3. **Compare Production vs. Non-Prod Environments** (Free)
      - Python version, interpreter flags, OS, architecture, installed packages
      - Dev/staging often use smaller datasets or different DB configs
   4. **Verify Resource Limits & Cgroups** (Free)
      - `cat /proc/self/cgroup`, `systemctl show <service>`, `ulimit -v`
      - Production containers/VMs often have stricter memory limits than dev
   5. **Analyze Data Volume & Schema Differences** (Free)
      - Production data is typically 10-100x larger
      - Check if the script loads entire tables/JSON files into memory
      - Compare row counts, file sizes, or API response sizes
   6. **Check for Unbounded Accumulation** (Free)
      - Look for global lists/dicts/caches that grow per run or across runs
      - Check for missing `del`, `gc.collect()`, or generator exhaustion
   7. **Profile Memory Usage (Built-in Tools)** (Free)
      - `python -m tracemalloc -s cumulative script.py`
      - `objgraph.show_top` to find largest objects
